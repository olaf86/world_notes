# ノートテーマ FragmentShader 解説

## この資料の目的

この資料は、GLSL や GPU シェーダーを初めて読む開発者が、World Notes の
ノート背景を安全に理解・調整できるようにするための内部資料である。

対象コードは次の3つ。

- [`note_theme_motion_background.dart`](../../lib/presentation/widgets/note/note_theme_motion_background.dart):
  Flutter 側の初期化、アニメーション、uniform 設定、フォールバック
- [`note_theme_background.frag`](../../shaders/note_theme_background.frag):
  GPU 上で各ピクセルの色を決める GLSL
- [`note_theme_motion_background_test.dart`](../../test/note_theme_motion_background_test.dart):
  読み込み、アニメーション、乱数シード、シームレスループのテスト

このシェーダーは写真のような複雑な表現を目的にしていない。ノート本文の
可読性を保ちながら、低コストな幾何学模様でテーマの違いを伝える装飾層で
ある。背景のベース色は `NoteThemePalette` のグラデーションが担当し、
FragmentShader はその上に半透明で重なる。

## 最初に押さえる全体像

描画までの流れは次のとおり。

```text
pubspec.yaml
  └─ .frag を Flutter のビルド対象として登録
       ↓ ビルド時にコンパイル
FragmentProgram.fromAsset(...)
  └─ コンパイル済みプログラムをアプリ全体でキャッシュ
       ↓ Widget ごとに1回生成
FragmentShader
  └─ サイズ、進行度、乱数シード、テーマ、色を uniform で受け取る
       ↓ CustomPainter が全面矩形を1回描画
GPU が矩形内の各ピクセルに対して main() を並列実行
       ↓
fragColor が既存グラデーションへ半透明合成される
```

重要なのは、Dart が円や葉を1個ずつ GPU へ送っているわけではない点である。
Dart は「この矩形をこのシェーダーで塗る」と1回指示する。シェーダーは、現在
処理中のピクセル座標から「このピクセルは円の輪郭に近いか」「罫線に近いか」
を計算して色を返す。

## GLSL と FragmentShader の基礎

### FragmentShader とは

FragmentShader は、最終的に画面へ描かれる各ピクセルの色を計算する小さな
プログラムである。概念的には次の関数に近い。

```text
色 = shader(現在のピクセル座標, 時間, テーマ, 色, 乱数シード)
```

同じ処理が多数のピクセルで並列に実行される。したがって、1回の計算が小さく
ても、全画面では「画面のピクセル数 × fps」回実行される。ループ、テクスチャ
参照、反復ノイズ、過剰な三角関数を避けているのはこのためである。

FragmentShader は通常、前フレームの値を覚えていない。この実装の動きは、
Dart から毎フレーム渡される `uProgress` を使って毎回計算し直している。

### このコードで使う型

| GLSL 型 | 意味 | 例 |
| --- | --- | --- |
| `float` | 1つの小数 | 進行度、透明度、距離 |
| `vec2` | 2つの小数 | `(x, y)` 座標、画面サイズ |
| `vec3` | 3つの小数 | RGB 色、ハッシュ計算用の3値 |
| `vec4` | 4つの小数 | RGBA 色 |
| `mat2` | 2×2 行列 | 座標の回転 |

GLSL では、ベクトル同士の四則演算が成分ごとに適用される。

```glsl
vec2 point = vec2(0.2, 0.4);
point *= vec2(2.0, 3.0); // (0.4, 1.2)
```

`.rgb`、`.xy`、`.x` のような記法は「成分を取り出す」という意味で、swizzle
と呼ばれる。

```glsl
uPrimary.rgb // vec4 から RGB の3成分を取り出す
uSize.x      // 幅だけを取り出す
```

### よく使う組み込み関数

| 関数 | このシェーダーでの用途 |
| --- | --- |
| `sin`, `cos` | 周期運動、回転。1周後に同じ値へ戻せる |
| `abs` | 線や中心からの符号なし距離 |
| `length` | 点から中心までの距離。円・楕円を作る |
| `floor` | 小数を切り捨て、セル番号を得る |
| `fract` | 小数部分だけを得て、模様を繰り返す |
| `mix(a, b, t)` | `t=0` なら `a`、`t=1` なら `b`、途中なら補間 |
| `step(edge, x)` | 閾値より小さいか大きいかを 0/1 で分ける |
| `smoothstep(a, b, x)` | 境界を滑らかに0から1へ変化させる |
| `min`, `max`, `clamp` | 距離や透明度の範囲を制限する |
| `dot` | ベクトルの内積。ここでは軽量ハッシュに使う |

`step` は硬い境界、`smoothstep` はぼかした境界を作ると考えるとよい。

## 座標の考え方

### ピクセル座標から UV 座標へ

`FlutterFragCoord().xy` は現在処理中のピクセル位置である。たとえば幅390、
高さ844の画面右下付近なら、おおよそ `(389, 843)` になる。

```glsl
vec2 uv = FlutterFragCoord().xy / max(uSize, vec2(1.0));
```

画面サイズで割ると、左上 `(0, 0)`、右下 `(1, 1)` に近い UV 座標になる。
端末サイズに依存せず同じ式を使えるのが利点である。`max(..., 1.0)` はゼロ除算
を防ぐ防御処理である。

このシェーダーでは次の座標系を使う。

```text
(0, 0) ───────── (1, 0)
  │                  │
  │       UV         │
  │                  │
(0, 1) ───────── (1, 1)
```

Flutter の画面座標と同じく、`y` は下へ行くほど大きくなる。

### アスペクト比補正

UV 空間では横幅も縦幅も1なので、縦長画面上の「UV上の円」は実際には横長に
見える。Citrus と Botanical では次の補正を入れている。

```glsl
point.x *= uSize.x / max(uSize.y, 1.0) * cells.y / cells.x;
```

この補正を削除すると、端末やカードの縦横比によって果実や葉の形が大きく
変わる。形状を調整するときは複数の縦横比で確認する。

## Flutter 側の初期化

### 1. アセット登録とビルド時コンパイル

`pubspec.yaml` の `flutter.shaders` に `.frag` を登録している。

```yaml
flutter:
  shaders:
    - shaders/note_theme_background.frag
```

通常のテキストアセットとは異なり、Flutter のビルド工程が端末で実行可能な
形式へコンパイルする。GLSL の構文や利用できない機能に問題がある場合、
`flutter test` やアプリのビルド時に失敗する。

### 2. FragmentProgram の読み込み

`NoteThemeShaderProgram.load()` は次を実行する。

```dart
ui.FragmentProgram.fromAsset('shaders/note_theme_background.frag');
```

`FragmentProgram` はコンパイル済みプログラム本体である。static な Future として
キャッシュするため、背景Widgetが複数あってもアセット読み込みは原則1回だけに
なる。

### 3. FragmentShader インスタンスの生成

読み込んだ `FragmentProgram` から、各背景Widgetが `fragmentShader()` を1回呼ぶ。
`FragmentShader` はuniform値を保持するため、同時に表示されるWidget間で共有
しない。プログラム本体は共有し、可変なuniformバッファだけをWidgetごとに持つ
構成である。

毎フレーム `fragmentShader()` を呼ばずインスタンスを再利用することで、uniform
バッファとネイティブオブジェクトの再確保を避けている。Widget破棄時には
`dispose()` してGPU側リソースを解放する。

### 4. 非同期ロード中と失敗時

Shaderは非同期に読み込む。完了するまで、または読み込みに失敗した場合は、
同じ `CustomPainter` に実装されたCanvasフォールバック描画を利用する。
ロード成功後は `fragmentShader != null` となり、Canvas版のテーマ別関数は通らない。

Standard テーマは意図的に装飾を持たないため、Shader自体を要求しない。

## uniform: Dart から GLSL へ渡す値

`uniform` は、1回の矩形描画中は全ピクセルで共通の入力値である。ピクセルごとに
異なるのは `FlutterFragCoord()` で得る座標であり、画面サイズや時刻、テーマ色は
uniform で渡す。

GLSL の宣言順とDartの `setFloat()` のインデックスは必ず一致させる。

| float index | GLSL uniform | 成分 | 内容 |
| ---: | --- | --- | --- |
| 0–1 | `uSize` | x, y | 描画領域の幅、高さ |
| 2 | `uProgress` | — | 1周を0.0〜1.0で表した進行度 |
| 3 | `uSeed` | — | Widget生成時に決まり、生存中固定される乱数シード |
| 4 | `uTheme` | — | `NoteThemeId.index` |
| 5 | `uOpacity` | — | カードやアーカイブ状態に応じた濃度倍率 |
| 6–9 | `uPrimary` | r, g, b, a | テーマのprimary色 |
| 10–13 | `uSecondary` | r, g, b, a | テーマのsecondary色 |
| 14–17 | `uTertiary` | r, g, b, a | テーマのtertiary色 |

たとえば `vec4` は4つのfloatなので、1つのuniformでも4インデックスを使う。
途中へ新しいuniformを追加した場合、後続インデックスがすべてずれる。Shaderが
真っ黒、色がおかしい、端末だけクラッシュする、といった問題の典型原因なので、
GLSLとDartを同じ変更で更新し、Shaderを実描画するテストを実行する。

最後に、Dart側は全面矩形を1回描く。

```dart
canvas.drawRect(Offset.zero & size, Paint()..shader = shader);
```

## アニメーション、repeat、シームレスループ

### 14秒、30fps、0.18の意味

- `_animationDurationSeconds = 14`: 背景が1周する時間
- `_targetRepaintsPerSecond = 30`: 背景の最大再描画fps
- `_animationSteps = 14 * 30 = 420`: 1周の描画段階数
- `_stillProgress = 0.18`: 1周の18%地点。約2.52秒地点の構図

14秒はFlutter、GLSL、GPUから要求される技術的な値ではなく、背景を見た直後に
動的な表現だと認識できる速度と、本文の背後で主張しすぎない速度のバランスを
取ったデザイン値である。周期を変更する場合は
`_animationDurationSeconds` だけを変更すれば、`_animationSteps` も追従する。

`AnimationController` 自体は端末のvsyncで通知するが、進行度を420段階へ量子化
する。同じ段階では `CustomPainter.shouldRepaint()` がfalseになるため、60Hzや
120Hz端末でも背景のGPU再描画は最大約30fpsに抑えられる。

`_stillProgress` は秒数でも透明度でもない。`animate: false` のカード／テーマ
プレビュー、OSの「アニメーションを減らす」が有効な場合、そして初期表示に
使う見栄えのよい固定位置である。

### 0〜1を0〜2πへ変換する理由

```glsl
float time = uProgress * PI * 2.0;
```

`sin(0)` と `sin(2π)`、`cos(0)` と `cos(2π)` は同じ値になる。進行度0で始まり、
進行度1で同じ座標へ戻るため、`AnimationController.repeat()` が1から0へ戻っても
位置が飛ばない。

乱数シードはrepeat時に再生成しない。同じWidgetが表示されている間は、形状の
個体差を保ったまま同じ14秒ループを繰り返す。画面を閉じて新しいWidgetが生成
されると、新しいシードになり別の構図になる。

### シームレスにするためのルール

時間を使う式は、進行度0と1で同じ結果にならなければならない。

安全な例:

```glsl
sin(time + phase)                 // 2π後に同じ値
cos(time + phase)                 // 2π後に同じ値
time * 2.0                        // 回転角なら2周して同じ向き
fract(position + uProgress)       // 1.0増えるので同じ小数部分
```

ジャンプを作る例:

```glsl
position + time * 0.018           // 1周後に中途半端な距離だけ移動
sin(time * 0.72)                  // 1周時点で正弦波が一周していない
rotation = time * randomSpeed     // randomSpeedが整数でなければ同じ向きに戻らない
```

現在のCitrusの回転は1周または2周の整数回転、Neonのスクロールは `fract` 内で
ちょうど1セル分、その他の移動は `sin` / `cos` にしている。

テストでは同じテーマ・シードを使い、`uProgress=0.0` と `1.0` を実際に64×96
ピクセルへ描画する。各RGBAチャンネルの最大差を1以下に制限し、浮動小数点の
丸め誤差だけを許容している。

## 疑似乱数の仕組み

このシェーダーの乱数は暗号学的乱数ではない。見た目に規則性を感じにくくする
ための、決定論的な疑似乱数である。

### `uSeed`

Dartの `math.Random().nextDouble()` で0〜1のシードをWidget生成時に1回作る。
フレームごとには生成しないため、ちらつかない。またCPUコストは無視できる程度
である。

### `seededValue(stream)`

画面全体で共通のランダム値を作る。`stream` を変えることで、同じシードから
オーロラ第1帯、オーロラ第2帯、Neonグリッドなど用途別の値を得る。

これは数回の乗算・加算・`fract` だけで、セル用ハッシュより軽い。ピクセルに
よって変える必要がないパラメータにはこちらを使う。

### `seededHash(cell)`

セル座標と `uSeed` から0〜1の値を作る。同じセルとシードなら常に同じ値になる。
果実や葉が描かれている間に大きさや色が突然変わらないのはこの性質による。

テクスチャベースのノイズや複数octaveのフラクタルノイズは使わず、乗算、
`fract`、`dot` だけの小さなハッシュに留めている。

### `remix(random)`

1つ目の乱数から別の見かけの値を作る。2回目の `seededHash` を呼ばずに済むため、
セルごとのGPUコストを減らせる。高品質な統計的乱数ではないが、装飾の位置、
方向、色を少し散らす用途には十分である。

## 共通ヘルパー

### `softLine`

```glsl
float softLine(float distanceToLine, float core, float feather)
```

対象の線からの距離を受け取り、線の中心に近いほど1、離れるほど0を返す。
`core` は完全に濃い範囲、`feather` は薄くなる幅である。アンチエイリアスと淡い
発光の両方に使う。

### `finish`

各テーマ関数は、色ごとの寄与を足した `premultipliedTint` と透明度 `alpha` を
`finish()` へ渡す。

`uOpacity` を掛けることで、同じShaderを詳細画面、カード、プレビューで濃度を
変えて再利用できる。最終alphaは0.32以下へ制限し、背景装飾が本文の可読性を
奪わないようにしている。

FlutterのCanvasへ渡す色はpremultiplied alpha、つまりRGBにもalphaを掛けた形式
にする必要がある。最後の `vec4(sourceColor * scaledAlpha, scaledAlpha)` がその
変換である。

## テーマ別処理

### Aurora

狙いは、3本の柔らかな光帯が上下に離れて流れる表現である。

1. `seededValue(1..3)` で3本それぞれの振幅、波長、開始位相を決める。
2. ピクセルの `uv.x` と `time` を `sin` へ入れ、そのx位置での帯の中心y座標を
   求める。
3. 現在の `uv.y` と中心yの差を取り、`softLine` で幅広くぼかす。
4. 3本をprimary、tertiary、secondaryで着色して加算する。

乱数は帯の性格を変えるが、`time` はすべてちょうど1周期なので14秒後に同じ
形へ戻る。テクスチャぼかしは使わず、距離から透明度を直接作っている。

### Citrus Pop

狙いは、サイズと向きの異なる柑橘断面がゆっくり動く表現である。

1. UVを `3.2 × 4.4` の仮想セルへ分割する。
2. `sin` / `cos` の小さな円運動をセル空間へ加える。
3. `floor` でセル番号、`fract - 0.5` でセル中心を原点とするローカル座標を得る。
4. セル番号を `seededHash` へ渡し、位置、大きさ、回転方向、色を決める。
5. 座標を `mat2` で回転する。
6. `length(point)` と果実半径の差で外皮の円を作る。
7. `y=0` と傾き±0.577の3直線までの距離で、6方向の房線を作る。

回転数は1周か2周の整数に限定している。ランダムな小数回転数にすると、14秒後
に開始角へ戻らずジャンプするためである。

### Botanical

狙いは、向き・細さの異なる葉が静かに揺れる表現である。

1. UVを `3.0 × 4.2` のセルへ分割する。
2. Citrusと同じく、小さな周期運動とセル単位の疑似乱数を適用する。
3. 乱数から葉の向き、長さ、幅、揺れ幅、色を決める。
4. 回転後の座標を縦横別に割って楕円距離を作る。
5. 葉先ほどy方向を強く縮める `taper` により、単純な楕円を葉らしく尖らせる。
6. `abs(point.y)` が小さい場所へ細い葉脈を描く。

葉の形状は厳密なベジェ曲線ではなく、距離場に近い計算で近似している。画面
全体で多数のパスを組み立てる必要がなく、1ピクセル内の算術だけで完結する。

### Neon Grid

狙いは、本数と間隔に適度なばらつきがある電子基板風の配線が、水平・垂直方向
だけで構成され、移動する交点で発光する表現である。

1. 画面を縦8セル、横5セルへ分け、行ごとに水平配線、列ごとに垂直配線の候補を
   1本ずつ作る。
2. 行番号／列番号と `uSeed` から疑似乱数を作り、配線の有無、セル内位置、段差の
   高さ、90度に折れる位置を決める。候補の一部を省くため、背景ごとに本数と空白
   幅が少しずつ異なる。
3. 水平配線は「水平→垂直→水平」、垂直配線は「垂直→水平→垂直」の3区間で
   構成する。斜線や曲線は使わず、すべて上下左右の線分に限定する。
4. `sin` / `cos` で各配線のセル内位置と折れ位置を小さく動かす。直角形状を保った
   まま二系統の相対位置が変わるため、交点が時間とともに移動する。
5. 各配線へ細い芯と淡いhaloを与え、水平・垂直両方のマスクが重なる場所だけへ
   tertiary色の強い芯と広い光を加える。配線はprimary／secondary、発光交点は
   tertiaryを使う。

配線の有無と基本形は固定シードから決まるため、アニメーション中に突然構成が
変わることはない。位置と折れ点の移動には1周期の三角関数だけを使い、14秒後に
完全に元の配置へ戻る。Shader非対応時のCanvas版も同じ3区間の直交パスを作り、
異なる系統の線分交差を計算して発光点を描く。

### Editorial

狙いは、紙面の罫線、左マージン、規則的なドットだけで構成する静かな編集紙面の
表現である。

1. UVを `8 × 12` の固定グリッドへ分割する。
2. 各行へ同じ長さの細い水平罫線を置き、4行ごとにわずかに濃い主罫線を作る。
3. x位置を固定した左マージン線を、primaryとtertiaryの中間色で描く。
4. グリッド交点へ低alphaのドットを置き、4つおきの規則的なパターンだけを少し
   大きく濃くする。
5. 強調ドットのalphaだけを1周期でわずかに変え、罫線とドットの位置は動かさない。

以前のランダムな矩形ブロックと不揃いな罫線長は使わない。規則性と余白を優先し、
本文の背後では印刷用紙のガイド程度に見える濃度へ抑えている。

## テーマ選択

`main()` の最後で `uTheme` に応じて1つの関数だけを呼ぶ。

| `NoteThemeId.index` | テーマ | Shader分岐 |
| ---: | --- | --- |
| 0 | Standard | Dart側でShaderを描画しない |
| 1 | Aurora | `uTheme < 1.5` |
| 2 | Citrus Pop | `uTheme < 2.5` |
| 3 | Botanical | `uTheme < 3.5` |
| 4 | Neon Grid | `uTheme < 4.5` |
| 5 | Editorial | 最後の `else` |

境界を1.5、2.5のようにしているのは、Dartから渡る整数相当のfloatを各テーマへ
分類するためである。

この実装はenumの並び順に依存する。`NoteThemeId` の途中へ新しい値を挿入すると
既存テーマのShader対応がずれるため、テーマ追加時はこの分岐とテストも同時に
更新する。より頻繁にテーマを追加する段階では、enum indexではなく明示的な
Shader ID をDart側で割り当てることを検討する。

## 負荷を抑える仕組み

現在の主な対策は次のとおり。

- 1背景につき全面矩形を1回だけ描画する
- 1回の描画ではテーマ分岐の1系統だけを実行する
- テクスチャサンプリングを使わない
- GLSL内にループを持たない
- 反復型ノイズや多段ブラーを使わない
- セルごとの本格ハッシュは原則1回とし、2つ目の値は `remix` で作る
- FragmentProgramをアプリ全体でキャッシュする
- FragmentShaderをWidget単位で再利用する
- 背景の再描画を最大30fpsへ量子化する
- カードとテーマプレビューは `animate: false` で静止させる
- OSのReduced Motion設定では静止させる
- `RepaintBoundary` で背景の再描画を周囲から分離する

ただしFragmentShaderは全面の全ピクセルで動くため、計算式が短くても処理コスト
がなくなるわけではない。次の変更は特に慎重に扱う。

- 複数octaveのnoise/fBMを追加する
- ピクセルごとの長いループを追加する
- 複数テクスチャをサンプリングする
- `pow`、`exp`、多数の三角関数を重ねる
- 60/120fpsへ戻す
- Shaderを複数レイヤーで全面描画する

表現を追加するときは、まず既存の `fract`、距離、`smoothstep`、1回のハッシュで
実現できないか検討する。

## 安全な調整手順

### 色を変える

Shaderへ色を直接ハードコードせず、`uPrimary`、`uSecondary`、`uTertiary` の
組み合わせとalpha係数を調整する。これによりlight/dark双方でテーマパレットを
維持できる。

### 模様の密度を変える

`cells` や `fract` 前の倍率を変更する。値を大きくすると模様が細かくなるが、
線が1ピクセル未満になるとちらつきやモアレが起きやすい。

### 動きを変える

`sin(time + phase)` の振幅を変えるのが最も安全である。速度を変える場合は
`sin(time * 2.0)` のように整数周期にする。0.7や1.5など、1周で元へ戻らない
倍率は使用しない。

### ランダム性を増やす

まず既存の `random` と `secondRandom` を別のパラメータへ割り当てる。新たな
`seededHash` 呼び出しは全ピクセルの計算量を増やす。セルごとに追加値が必要な
場合は、可能なら `remix` を連鎖して作る。

### uniformを追加する

1. GLSLのuniform宣言を追加する。
2. Dartの `setFloat` を同じ順序へ追加する。
3. 後続インデックスを確認する。
4. Shader対象テストを実行する。
5. iOS/Androidの少なくとも1台で目視確認する。

## テストと確認コマンド

Shader対象テスト:

```bash
flutter test test/note_theme_motion_background_test.dart
```

静的解析と全テスト:

```bash
flutter analyze
flutter test
```

自動テストが保証する内容:

- Standardに装飾を追加しない
- 5つの表現テーマに背景レイヤーがある
- FragmentProgramをアセットから読み込める
- Reduced Motionでは進行度が変わらない
- 通常時は進行度が変わる
- 乱数シードがアニメーション中に変わらない
- 5テーマすべてで進行度0と1の描画が一致する
- Neon Gridの直交配線と発光交点が時間経過で移動する

自動テストだけでは保証できない内容:

- 実機での主観的な美しさ
- 本文や画像との組み合わせでの読みやすさ
- 低性能端末でのフレーム時間と消費電力
- light/dark、縦長画面、カード、ボトムシートすべての見た目

リリース前はprofile/releaseモードの実機で、Flutter DevToolsのRaster時間と
目視を確認する。

## よくある不具合

### Shaderが表示されない

- `pubspec.yaml` の `flutter.shaders` 登録を確認する。
- `FragmentProgram.fromAsset` のキーが一致しているか確認する。
- alpha係数が0になっていないか確認する。
- debugログにロード失敗が出ていないか確認する。
- フォールバックCanvasが表示されているだけではないか確認する。

### 色がおかしい

- uniform宣言順と `setFloat` 順を確認する。
- RGBへalphaを二重に掛けていないか確認する。
- `finish()` を通してpremultiplied alphaにしているか確認する。

### 円や葉が潰れる

- `uSize` が正しく渡っているか確認する。
- アスペクト比補正を削除していないか確認する。
- 小さなカードで線幅やセル密度が高すぎないか確認する。

### 14秒ごとに位置が飛ぶ

- `uProgress=0` と `1` で同じ式の値になるか確認する。
- `time` へ掛ける速度が整数周期か確認する。
- 線形移動を `sin` / `cos` へ置き換えられないか検討する。
- 乱数シードをフレームごとに作り直していないか確認する。
- シームレスループの画素比較テストを実行する。

### GPU負荷が上がった

- Shader内の新しい関数が全ピクセルで何回呼ばれるか数える。
- 追加したハッシュ、三角関数、`pow`、ループ、テクスチャ参照を確認する。
- `animate: false` にできる小さな表示面がないか確認する。
- RepaintBoundaryと30fps量子化が維持されているか確認する。

## 用語集

| 用語 | 意味 |
| --- | --- |
| Fragment | 最終的なピクセル候補。ここではほぼピクセルと考えてよい |
| FragmentShader | 各Fragmentの色を計算するプログラム |
| GLSL | Shaderを記述するC言語風の言語 |
| RuntimeEffect | Flutterが実行時描画へ利用できるカスタムShader |
| uniform | 1回の描画中、全ピクセルで共通の入力 |
| UV | 画面を概ね0〜1へ正規化した2次元座標 |
| swizzle | `.rgb` や `.xy` のようなベクトル成分の選択 |
| 補間 | 2つの値の間を滑らかにつなぐこと |
| 距離場 | 形状までの距離から内外や輪郭を表す考え方 |
| premultiplied alpha | RGBへあらかじめalphaを掛けた色表現 |
| 疑似乱数 | シードと入力が同じなら同じ結果になる乱数風の値 |
| シームレスループ | 終了フレームと開始フレームがつながって見える繰り返し |
